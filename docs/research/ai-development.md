# AI駆動開発の課題とOrca / Stream Deckへの適用

調査日: 2026-11-07。一次資料を中心に確認。以下の研究結果と、この製品への適用仮説は別の主張である。

## 本質

生成を速めても、目的を定める・変更を理解する・必要な介入を見つける・正しさを検証するという人の仕事は残る。並列化では「いま自分が判断する必要があるもの」と「まだAI側が処理中のもの」を識別し、根拠のある画面へ戻るコストが増える。通知を増やすだけでも、自動承認するだけでも解決しない。

これはこのリポジトリへの適用仮説であり、本利用者の生産性を実測して確定した因果ではない。特に変更理解の負担は、キューを速く開くことだけでは減らせない。

| 症状                                   | 背後の課題                                 | 基本となる対策                                     | この組み合わせの適用範囲                                                             |
| -------------------------------------- | ------------------------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------------ |
| たくさん生成できるが出荷が速くならない | レビュー・統合・検証へ制約が移る           | 小さな変更、受入れ条件、検証の証拠、役割の分離     | 表示を完了判定にしない。コード品質そのものは判定しない。                             |
| 複数のAIを順に開いて質問待ちを探す     | 人の注意をどこへ向けるか分からない         | 状態の俯瞰と低コストな介入先への移動               | 常に見える物理キーに候補件数・対象・状態を出し、一押しで根拠画面へ戻す。             |
| 同じ返答を何度も見に行く               | 未確認と確認済みが区別されない             | 対象とイベントを限定した、人による明示確認         | 将来案。返答の通知だけを外すには新着や入力待ちを隠さない識別が必要。初版は見送る。   |
| 子の終了を全体の完了と思ってしまう     | 部分状態と成果の妥当性を混同する           | 親子関係・処理中・人の判断を分ける                 | 作業中の子が残る状態を完了と表示しない。待ちの宛先が分からない場合はその限界を残す。 |
| 切断しても「問題なし」に見える         | 観測できないことと対象がないことを混同する | 不明/一部取得/古い保持表示の明示、操作前の最新照合 | 取得失敗をゼロ件にしない。誤った相手への操作を止める。                               |
| 画面を開いても何の作業か思い出せない   | 意図・変更・判断の文脈が失われる           | 目的/根拠/履歴を残し、実装へ戻る入口を作る         | 小さな画面を全文チャットにせず、プロジェクト・対象と状態を識別し、詳細はOrcaへ。     |

## 採用候補と見送り

採用したのは、操作IDを追加設定せず、全ワークスペースから入力待ち・内容確認の候補を見つけ、明示操作でOrcaへ戻る「確認先を開く」キー。既存の固定ワークスペース表示とは役割を分ける。確認通知の非表示は見送り、同じ状態なら一巡後に再訪する代償を受け入れる。比較と独立批評への対応は [設計記録](../design/attention-workflow.md) を参照。

全面的な自律起動/一括承認/定型文の自動送信は見送る。生成量を増やし、監督と検証の負担をさらに増やし得る。固定IDの割り当て欄だけを増やす案は、対象の探索・新規ワークスペース追加の手間を残す。独立した通知音や強い点滅を増やす案も、割り込み負担を増やすため第一候補にしない。

## 実装可能性の確認

- Orca 1.4.229の `worktree ps --limit 200 --json` を実環境で読み取り、状態・親ペイン・状態開始時刻を確認した。スナップショットは8ワークスペース、今回観測した3エージェントに開始時刻があった。これは全環境のフィールド保証ではない。
- 人への質問と親エージェント向けの待ちを、公開CLIの状態だけですべて確実に区別できるとは確認できていない。製品では「人が必ず回答すべき件数」と断定しない。
- [Elgato SDK v2のキー](https://docs.elgato.com/streamdeck/sdk/v2/guides/keys/)・[ダイヤル](https://docs.elgato.com/streamdeck/sdk/v2/guides/dials/)は表示と明示操作の接続に使える。使用中の2.1.2向けガイドとローカルの型・CLI検証を照合する。SDK更新を本作業に抱き合わせない。
- 生産性向上の実証は対象外。受け入れ試験では、画面を総当たりせず候補へ到達する操作数、対象の一致、誤った副作用がないこと、状態と根拠が対応することを観測する。
